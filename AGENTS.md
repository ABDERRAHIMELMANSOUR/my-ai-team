# Repository instructions

## Purpose and scope

Coordinate web development and digital marketing deliverables using the role guides in `agents/`. Read the project brief and `docs/team-workflow.md` before starting a task. A role guide describes responsibilities; it does not grant access to external systems or authorization to publish.

## Execution

- Define the intended outcome, task owner, dependencies, and acceptance criteria.
- Keep work within the approved brief. Label assumptions and ask for missing decisions that block progress.
- Follow existing project conventions. When starting implementation, document the chosen stack and setup commands in its project README.
- Keep credentials in a secret manager or environment variables. Commit only redacted examples.
- Use relative Markdown links and descriptive file names.
- Validate changes appropriately: check document links for documentation; run relevant build, lint, accessibility, and behavior checks for code when those checks exist.
- Record the checks performed and any remaining limitations in the handoff.
- Obtain action-specific authorization before deploying, publishing externally, contacting people, or spending advertising budget.

## Coordination

The Team Lead manages scope and dependencies. Each role supplies a concise handoff with artifact paths, decisions, evidence, checks, and next steps. Review cross-discipline work with the affected role. Do not claim that planned work, tests, account connections, or results already exist.
